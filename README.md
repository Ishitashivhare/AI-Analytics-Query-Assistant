# AI Analytics Query Assistant

Converts natural language questions into SQL, executes them safely against a
selected data source, and returns structured results. Supports:

- SQLite database files
- MySQL databases
- CSV files loaded into a temporary SQLite database

Uses a local Ollama LLaMA 3 model for SQL generation, with streaming support.

## Folder Structure

```
ai-analytics-query-assistant/
├── api_server.py            # FastAPI app: /ask, /stream, /health endpoints
├── llama_sql_generator.py   # Prompt engineering + Ollama API calls
├── db.py                    # SQLite/MySQL/CSV adapters, schema discovery, SQL validation
├── file_utils.py            # Upload validation and temporary file helpers
├── models.py                # Pydantic request/response models
├── load_data.py             # Creates analytics.db and inserts sample sales data
├── index.html               # Frontend UI for data source selection and Q&A
├── requirements.txt         # Python dependencies
└── README.md
```

## Prerequisites

1. **Python 3.10+**
2. **Ollama** installed and running locally with the `llama3` model pulled:

   ```bash
   # Install Ollama: https://ollama.com/download
   ollama pull llama3
   ollama serve        # starts the Ollama API on http://localhost:11434
   ```

## Setup

```bash
# 1. Create and activate a virtual environment (recommended)
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Create the SQLite database and load sample data
python load_data.py

# 4. Start the API server
uvicorn api_server:app --reload --port 8000

# 5. Serve the frontend in another terminal
python -m http.server 5500

# Or launch both with one command
python run_app.py
```

Open the frontend at `http://localhost:5500/index.html`.
The API will be available at `http://localhost:8000`.
Interactive docs (Swagger UI): `http://localhost:8000/docs`

## Database Schema

```
Table: sales
  product     TEXT
  revenue     REAL
  clicks      INTEGER
  impressions INTEGER
  date        TEXT (YYYY-MM-DD)
```

10 sample rows are inserted automatically by `load_data.py`.

For uploaded SQLite files and MySQL databases, the schema is discovered dynamically.
For CSV files, the app reads the file with pandas, normalizes the headers, and loads the data into a temporary SQLite database.

## Endpoints

### `GET /health`
Checks API status and whether Ollama is reachable.

```bash
curl http://localhost:8000/health
```

### `POST /ask`
Converts a natural language question into SQL, executes it, and returns results.

```bash
curl -X POST http://localhost:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "What is the total revenue by product?", "source_id": "optional-source-id"}'
```

Example response:
```json
{
  "question": "What is the total revenue by product?",
  "sql": "SELECT product, SUM(revenue) as total_revenue FROM sales GROUP BY product ORDER BY total_revenue DESC",
  "result": [
    {"product": "Ergonomic Chair", "total_revenue": 8950.0},
    {"product": "Monitor 27in", "total_revenue": 6720.0}
  ],
  "row_count": 10,
  "error": null
}
```

More example questions:
```bash
curl -X POST http://localhost:8000/ask -H "Content-Type: application/json" \
  -d '{"question": "Which product has the highest click-through rate?"}'

curl -X POST http://localhost:8000/ask -H "Content-Type: application/json" \
  -d '{"question": "Show me all sales after 2024-01-08"}'

curl -X POST http://localhost:8000/ask -H "Content-Type: application/json" \
  -d '{"question": "What is the average revenue per product?"}'
```

### `POST /stream`
Streams a natural language answer from the LLM token by token (simulated typing effect).

```bash
curl -N -X POST http://localhost:8000/stream \
  -H "Content-Type: application/json" \
  -d '{"question": "Summarize the sales performance trends."}'
```

The `-N` flag disables curl's output buffering so you see tokens arrive live.

### Data source endpoints

- `POST /data-sources/sqlite/upload` with a multipart file field named `file`
- `POST /data-sources/csv/upload` with a multipart file field named `file`
- `POST /data-sources/mysql/connect` with JSON body:

```json
{
  "host": "localhost",
  "port": 3306,
  "database": "analytics",
  "username": "root",
  "password": "secret"
}
```

Each successful response returns a `source_id`, discovered schema, and a message. Send that `source_id` with `/ask` to query the selected source.

## Safety Guarantees

Every SQL query generated by the LLM passes through `db.validate_sql()` before
execution:

- Must start with `SELECT` (rejects INSERT/UPDATE/DELETE/DROP/ALTER/etc.)
- Blocks a list of forbidden keywords (DROP, DELETE, UPDATE, INSERT, ALTER,
  TRUNCATE, CREATE, PRAGMA, ATTACH, etc.)
- Rejects stacked/multiple statements (no `;`-separated queries)
- SQLite and MySQL execution errors are caught and returned as clean JSON errors
  instead of crashing the server

## Error Handling

- **Ollama unreachable** → `/ask` returns HTTP 503 with a clear message
- **Unsafe SQL generated** → `/ask` returns HTTP 200 with an `error` field
  explaining the rejection (SQL is still shown for transparency)
- **Invalid/failing SQL** → caught and returned as an `error` field, no crash
- **Empty result set** → returned normally with `"result": []` and
  `"row_count": 0`

Additional source-specific errors are handled for corrupted SQLite uploads,
empty or malformed CSV files, and MySQL connection failures.

## Notes

- Model used: `llama3` via `http://localhost:11434/api/generate`
- Temperature is set to `0.0` for SQL generation to keep output deterministic
- Logging is configured via Python's `logging` module and prints to stdout
